# 区间不相交 - 最大不相交区间数量

要求最大不相交区间的数量，最通用的两种方法是 **按右端点排序的贪心算法 和 dp ，数据结构优化**
## 一、贪心

贪心的算法很简单，只需要计算出区间后，按区间右端点排序，左端点通常从大到小排序(也可以不管)，然后遇到不重叠的就选择

贪心算法 时间复杂度为 $O(N \log N)$ 且 空间复杂度为 $O(1)$

- **计算区间**：首先算出每个区间的左端点 $t_i$ 和右端点 $s_i$。
    
- **按终点排序**：将所有区间按照**右端点 $s_i$ 从小到大**进行排序。右端点相同时，左端点按什么排都可以
    
- **贪心选择**：
    
    - 初始化一个指针 `last_end = -INF`，表示当前已选区间的最大右边界。
        
    - 遍历排序后的区间，如果当前区间的左端点 $t_i > \text{last\_end}$（即不重叠），则选择这个区间，并更新 `last_end = s_i`。
        
    - 如果重叠，则直接跳过该区间。

```c++
int cmp(const array<int, 2> & a, const array<int, 2> & b) {
    return a[1] < b[1];
}

int ap_greedy(vector<array<int, 2>> & a) {
    sort(a.begin(), a.end(), cmp);

    int n = a.size();
    int ans = 0;
    long long cur_end = -2e9; // 初始哨兵，等价于你的 end[0]

    for (int i = 0; i < n; i++) {
        // 题目要求：端点重合也是重合 -> 当前左端点必须严格大于上一个右端点
        if (a[i][0] > cur_end) {
            ans++;
            cur_end = a[i][1]; // 选了当前区间，更新右端点
        }
        // 不满足条件则直接跳过（等价于不选/删除）
    }

    return ans;
}
```

## 为什么可贪心
### 1. 核心数学性质

- **最优子结构（Optimal Substructure）**：
    
    一个问题的最优解包含其子问题的最优解。例如：如果你选了区间 $A$，那么剩下的空间里，你必须也选出最多的不相交区间。
    
- **贪心选择性质（Greedy Choice Property）**：
    
    可以通过做出局部最优（当下最好）的选择，来达到全局最优。换句话说，**当前做出的贪心选择，绝对不会把后面的路堵死**。
    

### 2. 经典证明方法：反证法（或者叫“替换法”）

要证明一个贪心算法是正确的，最常用的方法是**替换法（Exchange Argument）**：假设存在一个“外星人”给出的绝对完美的全局最优解，我们证明可以用我们的贪心选择去替换它的第一步，且替换后结果不会变差。


### 想象一个场景：

假设有许多区间，我们的贪心策略是：**每次都选右端点最早结束的区间**。

- 设贪心算法选出的区间集合为：$G = \{g_1, g_2, \dots, g_k\}$
    
- 假设存在一个真正的、完美的最佳答案集合为：$O = \{o_1, o_2, \dots, o_m\}$
    

我们需要证明 $k = m$（即贪心选出的数量和完美答案数量一样多）。

### 证明步骤：

1. **比较第一个区间**：
    
    根据贪心策略， $g_1$ 是所有区间里**结束最早**的。而完美答案的第一个区间是 $o_1$。
    
    显然， $g_1$ 的结束时间 $\le o_1$ 的结束时间。
    
2. **进行替换**：
    
    如果 $g_1 = o_1$，两边打平。
    
    如果 $g_1 \neq o_1$，因为 $g_1$ 结束得比 $o_1$ 还要早（或者一样早），如果我们把完美答案 $O$ 里的 $o_1$ 扔掉，换成 $g_1$，由于 $g_1$ 占用的时间更少，它**绝对不会与 $O$ 集合中剩下的元素 $\{o_2, o_3, \dots\}$ 发生冲突**。
    
3. **推导结论**：
    
    替换之后，新集合的区间数量没有变少，而且依然合法。这意味着，**第一步选择贪心解，绝不会比选择其他解更差**。
    

同理，对于第二步、第三步……我们都可以用贪心解去替换完美解里的对应项。这就证明了，贪心算法一路走到底，最后得到的数量一定和完美答案一样多（$k = m$）。

## 二、动态规划

虽然**区间不相交数量** 问题用贪心算法是最优解，但使用动态规划（DP）不仅能加深对问题的理解，还能轻松应对一些贪心无法解决的变体（例如：每个区间带有不同权重，求最大权重和）。

### 状态转移方程

1. **预处理**：同样需要将区间按照**右端点**从小到大排序。
    
2. **状态定义**：设 $dp[i]$ 表示在前 $i$ 个区间中，能选择的最多不重合区间数量。
    
3. **状态转移**：对于第 $i$ 个区间，我们有两种选择：
    
    - **不选第 $i$ 个区间**：此时的最大数量等于前 $i-1$ 个区间的最大数量，即 $dp[i] = dp[i-1]$。
        
    - **选第 $i$ 个区间**：我们需要在排序后的前 $i-1$ 个区间中，找到**最后一个与区间 $i$ 不重合**的区间 $j$（即满足 $intervals[j][1] \lt intervals[i][0]$）。此时 $dp[i] = dp[j] + 1$。
        
    - **综上所述**：$dp[i] = \max(dp[i-1], dp[j] + 1)$。
        

由于区间已经按右端点排序，找这个合法的区间 $j$ 可以通过二分查找（Binary Search）来优化。
```c++
int cmp(const array<int, 2> & a, const array<int, 2> & b) {
    return a[1] < b[1];
}

int ap_dp(vector<array<int, 2>> & a) {
    sort(a.begin(), a.end(), cmp);

    int n = a.size();
    vector<int> dp(n + 1, 0), end(n + 1, -2e9);
    for (int i = 0; i < n; i++) {
        //不选
        dp[i + 1] = dp[i];

        //选
        end[i + 1] = a[i][1];
        int j = lower_bound(end.begin(), end.begin() + i + 1, a[i][0]) - 1 - end.begin();// [0, i] <
        //end[0] = -2e9，如果没有找到符合的，j = 0， dp[0] = 0, dp[0] + 1 = 1.
        //总可以取到单独的一个区间，所以不影响。当然，特判continue也可以
        dp[i + 1] = max(dp[i + 1], dp[j] + 1);
        
    }

    return dp[n];
}
```

| **维度**    | **贪心算法 (Greedy)**                   | **动态规划 (DP + 二分)**                                    |
| --------- | ----------------------------------- | ----------------------------------------------------- |
| **核心思想**  | 每次都选**右端点最早结束**的区间，给后面留尽可能大的空间。     | 考虑选或不选当前区间，选的话就**二分向前追溯**首个不冲突的状态。                    |
| **时间复杂度** | $O(N \log N)$ （瓶颈在排序，遍历仅需 $O(N)$）   | $O(N \log N)$ （排序 $O(N \log N)$ + 遍历二分 $O(N \log N)$） |
| **空间复杂度** | $O(1)$ （除去排序开销）                     | $O(N)$ （需要 `dp` 数组和 `end` 数组）                         |
| **代码常数**  | 极小，运行速度极快。                          | 略大，有数组读写和二分查找的开销。                                     |
| **算法扩展性** | **弱**。如果每个区间加上“权重/价值”，求最大价值，贪心直接失效。 | **强**。带权重时只需将 `dp[j] + 1` 改为 `dp[j] + weight[i]` 即可。  |


# 区间最大覆盖点

给你 $n$ 个新区间 $[l_i, r_i]$，请问**哪个坐标 $x$ 被覆盖的次数最多**？求出这个最大覆盖次数。



下 # 区间最大覆盖线段

给你 $n$ 个新区间 $[l_i, r_i]$，以及一个长度为k的线段，请问**怎么才能使线段覆盖的区间数量最多**？求出这个最大覆盖的区间数量。

假设线段的起点为L，即 放置一个长度为 $k$ 的“固定窗口” $[L, L+k]$，去尽可能多地覆盖（触碰）已有的区间。

### 1. 核心数学转换：什么时候会相交？

设小红选定的区间为 $[L, L+k]$。对于任意一个给定的区间 $[l_i, r_i]$，它们相交的条件是什么？

由于端点重合也算相交，它们**不相交**只有两种情况：

1. 给定区间完全在小红区间的左边：$r_i < L$
    
2. 给定区间完全在小红区间的右边：$l_i > L+k$
    

取反过来，它们**相交**的充要条件就是：

$$r_i \ge L \quad \text{且} \quad l_i \le L+k$$

我们把这个不等式组变形，全部用 $L$ 来约束：

$$L \le r_i \quad \text{且} \quad L \ge l_i - k$$

合并起来就是：

$$l_i - k \le L \le r_i$$

**大白话总结：** 每一个给定的区间 $[l_i, r_i]$，只要小红选择的左端点 $L$ 落在 $[l_i - k, r_i]$ 这个范围内，这个区间就能和小红的区间相交！

### 2. 问题转化：转换成“区间最大覆盖点”

现在问题变成了：给你 $n$ 个新区间 $[l_i - k, r_i]$，请问**哪个坐标 $L$ 被覆盖的次数最多**？求出这个最大覆盖次数。

这种问题可以用差分、双指针、贪心+二分

### 一、差分
(差分做法很简单易懂，代码简洁，更好使用)
```c++
void ap() {
    int n, k; cin >> n >> k;
    map<int ,int> d;
    for (int i = 0; i < n; i++) {
        int l, r; cin >> l >> r;
        d[l - k]++;
        d[r + 1]--;
    }
     
    int s = 0;
    int ans = 1;
    for (auto & [x, v] : d) {
        s += v;
        ans = max(ans, s);
    }
     
    cout << ans;
     
    return ;
}
```

### 二、双指针
我们可以把所有区间的左端点经过变换后的 $l_i - k$ 收集起来，右端点 $r_i$ 也收集起来，分别升序排序。

- 想象小红的窗口左端点 $L$ 从左向右移动。
    
- 当 $L$ 遇到了某个区间的变换后左端点 $l_i - k$ 时，说明该区间**开始与窗口相交**，相交数量 $+1$。
    
- 当 $L$ 严格大于某个区间的右端点 $r_j$ 时（即 $L > r_j$），说明窗口已经走过了这个区间，该区间**脱离相交状态**，相交数量 $-1$。
    

用代码格式来实现，我们可以对 $L$ 的可能取值（即所有的 $l_i - k$）进行排序，用一个指针维护有多少区间已经失效。
```c++
void ap() {
    int n, k; cin >> n >> k;
    vector<int> L(n), R(n);
    for (int i = 0; i < n; i++) {
        cin >> L[i] >> R[i];
        L[i] -= k; // 变换左端点
    }

    sort(L.begin(), L.end());
    sort(R.begin(), R.end());

    int ans = 0, r_ptr = 0;
    // 遍历每一个变换后的左端点，用 r_ptr 动态剔除过期区间
    for (int l_ptr = 0; l_ptr < n; l_ptr++) {
	    int x = L[l_ptr];//相当于我们上面说的L
        while (r_ptr < n && R[r_ptr] < x) {
            r_ptr++; // 右端点严格小于当前 L，说明该区间已失效
        }
        ans = max(ans, l_ptr - r_ptr + 1); // 当前有效区间数 = 已进来总数 - 已失效数
    }

    cout << ans;
    return;
}
```

### 三、贪心 + 二分

```c++
void ap() {
    int n, k; cin >> n >> k;
    vector<int> s, e;
    for (int i = 0; i < n; i++) {
        int l, r; cin >> l >> r;
        s.push_back(l), e.push_back(r);
    }
     
    sort(s.begin(), s.end());
    sort(e.begin(), e.end());
     
    int ans = 1;
    for (int i = 0; i < n; i++) {
        int L = e[i];
        int R = L + k;
        
        auto p = lower_bound(s.begin(), s.end(), R + 1) - s.begin() - 1;//<= R
        
        ans = max(ans,  p - i + 1);
    }
    cout << ans;
     
    return ;
}
```

### 双指针方法详解

#### 分离排序

这是这个双指针算法最巧妙的地方：

```
sort(L.begin(), L.end());
sort(R.begin(), R.end());
```

我们把所有的“生效时间点（$l_i-k$）”和“失效时间点（$r_i$）”解耦了。

因为我们只关心“当前这一刻，有多少区间已经开始，且还没有结束”，至于当前生效的这个区间到底对应原来的哪一个右端点，根本不重要。这就好比商场统计在馆人数：只要知道进来了几个人、出去了几个人就行，不需要知道具体是谁进出。


“分离排序”确实是整个算法中最反直觉、最抽象的部分。

这样解释还是有些晦涩难懂，下面用更具体的例子解释

#### 1. 为什么可以把 L 和 R 拆开单独排序？

**故事场景**：

有一家游乐场，今天一共来了 3 个旅行团（相当于 3 个区间）。

- 1 团：1 点进场，3 点离场
    
- 2 团：2 点进场，5 点离场
    
- 3 团：4 点进场，6 点离场
    

现在，游乐场老板交给你一个任务：**“不要管他们是哪个团的，我只要知道今天哪个时间点，游乐场里的‘总人数（同时在场团数）’最多？”**

为了完成这个任务，你需要分别统计“进场时间表”**和**“离场时间表”：

- **所有进场时间 (L)**：`[1, 2, 4]` （已经从小到大排好序）
    
- **所有离场时间 (R)**：`[3, 5, 6]` （已经从小到大排好序）
    

**核心关键**：当你把这两个表各自排序后，你把 1 团的进场时间和它的离场时间**解耦（拆散）**了。但这完全不影响你统计总人数！因为商场算“当前有几个人”，只需要知道**“截止到目前进来了几个人”**减去**“截止到目前出去了几个人”**。

#### 2. 双指针控制：一步步计算个数

现在，你拿张椅子坐在游乐场大门口，手里拿着这两个排好序的表。我们用 `l_ptr` 指向进场表，`r_ptr` 指向离场表。

#### 🚀 第一步：当 `l_ptr = 0` 时

- 当前有人进场了，进场时间 `L[0] = 1` 点。
    
- **计算历史总进场数**：因为 `l_ptr` 是下标（从 0 开始），说明到目前为止，历史上总共进来了 `l_ptr + 1 = 1` 个团。
    
- **检查有没有人离场**：你看一眼离场表最早的时间 `R[r_ptr]`（即 `R[0] = 3` 点）。现在才 1 点，3 点还没到呢，所以没人离场。`while` 循环不执行，`r_ptr` 依然是 `0`。
    
- **结算当前在场人数**：
    
    $$\text{当前在场} = \text{历史总进场} - \text{历史总离场} = 1 - 0 = 1$$
    
    （即：`l_ptr - r_ptr + 1 = 0 - 0 + 1 = 1`）
    

#### 🚀 第二步：当 `l_ptr = 1` 时

- 时间来到了 `L[1] = 2` 点，又有一个团进场。
    
- **计算历史总进场数**：历史上总共进来了 `1 + 1 = 2` 个团。
    
- **检查有没有人离场**：最早的离场时间还是 `R[0] = 3` 点。现在才 2 点，3 点依然没到，没人离场。`while` 循环不执行，`r_ptr` 依然是 `0`。
    
- **结算当前在场人数**：
    
    $$\text{当前在场} = \text{历史总进场} - \text{历史总离场} = 2 - 0 = 2$$
    
    （即：`l_ptr - r_ptr + 1 = 1 - 0 + 1 = 2`）
    

#### 🚀 第三步：当 `l_ptr = 2` 时（核心转折点点！）

- 时间来到了 `L[2] = 4` 点，第三个团进场。
    
- **计算历史总进场数**：历史上总共进来了 `2 + 1 = 3` 个团。
    
- **检查有没有人离场**：现在是 4 点了！你开始看离场表：
    
    - 最早离场的 `R[0] = 3` 点。哦！3 点小于现在的 4 点，这个人**已经走了**。于是你把离场人数记录加 1，`r_ptr` 变成 `1`。
        
    - 接着看下一个离场时间 `R[1] = 5` 点。5 点大于现在的 4 点，还没走。`while` 循环结束。
        
- **结算当前在场人数**：
    
    历史上总共进来了 3 个团，但是通过刚才的检查，已经有 1 个团（`r_ptr = 1`）在 3 点的时候彻底离开了。
    
    $$\text{当前在场} = \text{历史总进场} - \text{历史总离场} = 3 - 1 = 2$$
    
    （即：`l_ptr - r_ptr + 1 = 2 - 1 + 1 = 2`）
    

#### 3. 公式 `l_ptr - r_ptr + 1` 的终极大白话

不要把它当成一个高深的数学公式，它其实就是：

$$\text{ans} = (\text{l\_ptr} + 1) - \text{r\_ptr}$$

- **`l_ptr + 1`**：由于数组下标从 0 开始，当循环指针走到 `l_ptr` 时，意味着在坐标轴上，**排在当前时间点左边的“区间起点”已经全部被触发了**。这就代表“历史上总共入场的数量”。
    
- **`r_ptr`**：`while` 循环的作用是，只要发现有区间的终点 `R[r_ptr]` **严格小于**当前的时间点，就说明这个区间在过去已经死掉了。`r_ptr` 往前走几步，就代表“历史上总共死掉了多少个区间”。
    
- **两者相减**：既然总共出生了 3 个，死掉了 1 个，那当前这一刻活着的区间数量，自然就是 $3 - 1 = 2$ 个。
    

因为左右端点都各自排好了序，随着 `l_ptr` 不断向右移动，时间线只能往后推，所以死掉的区间只会变多、不会诈尸复活。这就是为什么 `r_ptr` 不需要回退，只需一路向右单调累加即可。



### 贪心 + 二分 方法详解

#### 核心数学贪心策略：为什么枚举 $L = e[i]$？

小红可以任意选择一个长度为 $k$ 的区间 $[L, L+k]$。为了让这个窗口撞上尽可能多的给定区间，**最优的 $L$ 一定会卡在某个给定区间的右端点上。**

- **为什么？** 如果你随意把窗口放在一个空位，尝试把它往左移动。直到窗口的左端点 $L$ 刚好贴在某个区间的右端点（即 $L = e[i]$）时，窗口覆盖右侧区间的范围达到了最大，而左侧原本相交的区间也还没有滑出窗口。 
- 为什么一定更优？ 类似dp，我们枚举 窗口和每一个区间都有相交，在这个基础上再看和其他区间的相交情况，我们会发现，在区间右端点时，满足和这个枚举的区间相交，同时还更优地留出了更多的空间给右边的相交可能。因此我们不仅达成了目的，还使得全局更优
    
- 因此，直接枚举所有的 `e[i]` 作为窗口的左端点 $L$，就必然能涵盖到全局的最优解。此时窗口的右端点固定为 $R = L + k = e[i] + k$。


#### 如何计算个数？

我们要紧紧抓住核心公式
$$l_i \le R \quad \text{且} \quad r_i \ge L $$
枚举右端点的时候，满足 $r_i \ge L$  的下标为 i,  i + 1, i + 2 ... n - 1
				满足$l_i \le R$   的下标为 p,  p - 1, p - 2 ... 0

这里的p 是我们二分找到的
```c++
auto p = lower_bound(s.begin(), s.end(), R + 1) - s.begin() - 1;//<= R
```

那么问题来了，为什么答案就是 p - i + 1 呢？
虽然这个下标范围就是合法的，但是这个显然是拆开来的，不是一整个区间的下标！

我们潜意识里认为：**“万一满足条件的左端点，和满足条件的右端点，拼出来的不是同一个区间怎么办？”**

结论：**“左边死掉的”和“右边死掉的”，绝对不可能是同一个区间。**
#### 为什么一个区间不能“同时在左边死掉，又在右边死掉”？

我们用反证法来推导。假设存在一个神奇的区间，它同时在两边死掉了：

1. 因为它在**左边死掉了**（太靠左），说明它的右端点严格小于窗口左界：
    
    $$r < L$$
    
2. 因为它在**右边死掉了**（太靠右），说明它的左端点严格大于窗口右界：
    
    $$l > R$$
    
3. 别忘了，小红的窗口右界本身就比左界大（$R = L + k$，且 $k \ge 0$），所以天然有：
    
    $$L \le R$$
    

现在，我们把这三个不等式像糖葫芦一样串起来：

$$r < L \le R < l$$

最终推导出了：

$$r < l$$

**这就翻车了！** 右端点 $r$ 居然严格小于左端点 $l$？这在数学上代表这个区间的长度是**负数**（比如 $[5, 2]$），这在现实中是不存在的。题目明确给出了 $l_i \le r_i$。

因此，一个合法的区间，**要么太靠左死掉，要么太靠右死掉，要么活着（相交）。它绝对不可能分身成两半，同时在左边和右边死掉。**

#### 2. 用“游乐场”来看，就是“昨天”和“明天”的区别

我们再退回到游乐场的场景。小红的窗口 $[L, R]$，就像是游乐场“今天”的营业时间。

- **太靠左死掉的区间**：代表这个旅行团在“昨天”（$r < L$）就已经离开游乐场了。
    
- **太靠右死掉的区间**：代表这个旅行团在“明天”（$l > R$）才会到达游乐场。
    

请问，有没有可能存在一个旅行团，它既是“昨天就已经离开”的，又是“明天才准备入场”的？

绝对不可能。它们是完全互斥的两拨人。

#### 3. 终极闭环

既然这两拨死掉的区间**完全没有交集**，那么我们在用总数 $n$ 去减它们的时候：

$$\text{总数 } n - \text{昨天走的} - \text{明天来的} = \text{今天在场的}$$

这个减法就是纯粹的、干净的扣除，中途**不需要加上重复扣除的部分**（因为重复部分为 0）。




# 区间合并

[56. 合并区间 - 力扣（LeetCode）](https://leetcode.cn/problems/merge-intervals/description/)

```c++
vector<vector<int>> merge(vector<vector<int>>& intervals) {
    sort(intervals.begin(), intervals.end());
    vector<vector<int>> ans;
    int start = intervals[0][0], end = intervals[0][1];
    for (auto & p : intervals) {
        int s = p[0], e = p[1];
        if (s <= end) {
            end = max(end, e);
        } else {
            ans.push_back({start, end});
            start = s;
            end = e;
        }
    }
    ans.push_back({start, end});
    return ans;
}
```

# 最少区间覆盖

给你 $n$ 个闭区间，以及一个目标闭区间 $[S, T]$，让你从这 $n$ 个区间中**挑出最少的区间**，把目标区间 $[S, T]$ 连绵不断地完全覆盖掉。

为了完成这个任务，我们的贪心策略是：**“步子迈得越远越好，用最少的步数跨到终点。”** 这就引出了排序规则：**按左端点从小到大排序；若左端点相同，按右端点从大到小排序。**


# 删除被覆盖区间

[1288. 删除被覆盖区间 - 力扣（LeetCode）](https://leetcode.cn/problems/remove-covered-intervals/description/?envType=daily-question&envId=2026-07-06)

```c++
class Solution {
public:
    int removeCoveredIntervals(vector<vector<int>>& intervals) {
        // 按区间左端点从小到大排序
        // 区间左端点相同时，按区间右端点从大到小排序，这样会先遍历大区间，再遍历被大区间覆盖的小区间
        ranges::sort(intervals, {}, [](auto& a) { return pair(a[0], -a[1]); });

        int ans = 0;
        int max_right = 0; // 已遍历区间中的最大右端点
        for (auto& p : intervals) {
            // 由于区间左端点是从小到大排序的，已遍历区间的左端点都 <= 当前区间的左端点
            // 如果当前区间右端点 <= max_right，说明当前区间被另一个区间覆盖，否则没被覆盖
            if (p[1] > max_right) {
                max_right = p[1];
                ans++; // 当前区间没被覆盖
            }
        }
        return ans;
    }
};
```
