# 字典树原理

## 指针版 Trie

```c++
struct Node {
    Node * son[26]{};
    bool end = false;
};

class Solution {
    Node * root = new Node();

public:
    void insert(string s) {
        Node * cur = root;
        for (char c : s) {
            c -= 'a';

            if (cur->son[c] == NULL) {
                cur->son[c] = new Node();
            }

            cur = cur->son[c];
        }
        cur->end = true;
    }

    bool query(string s) {
        Node * cur = root;
        for (char c : s) {
            c -= 'a';

            if (cur->son[c] == NULL) return false;

            cur = cur->son[c];
            if (!cur->end) return false;
        }

        return true;
    }

};
```

## 静态数组版模板

```c++
// 静态数组实现的 Trie，内存一次性分配，无指针和动态扩容开销
// MAXN: 最大可能产生的节点总数 (约等于 总字符数 + 5)
// A: 字符集大小 (默认 26 小写字母)
// F: 字符集起始字符 (默认 'a')
template <int MAXN = 150005, int A = 26, char F = 'a'>
struct Trie {
    int tree[MAXN][A];
    int end_cnt[MAXN];
    int pass_cnt[MAXN];
    int cnt;

    Trie() {
        build();
    }

    // 初始化/重置字典树
    void build() {
        cnt = 1;
        memset(tree[1], 0, sizeof(tree[1]));
        end_cnt[1] = 0;
        pass_cnt[1] = 0;
    }

    // 映射字符到对应下标 [0, A-1]
    int id(char c) const {
        return c - F;
    }

    // 插入字符串
    void insert(const string& word) {
        int cur = 1;
        pass_cnt[cur]++;
        for (char c : word) {
            int path = id(c);
            if (tree[cur][path] == 0) {
                tree[cur][path] = ++cnt;
                // 新建节点时清空其状态（避免多组测试用例时被脏数据污染）
                memset(tree[cnt], 0, sizeof(tree[cnt]));
                end_cnt[cnt] = 0;
                pass_cnt[cnt] = 0;
            }
            cur = tree[cur][path];
            pass_cnt[cur]++;
        }
        end_cnt[cur]++;
    }

    // 查询字符串完全匹配出现的次数
    int search(const string& word) const {
        int cur = 1;
        for (char c : word) {
            int path = id(c);
            if (tree[cur][path] == 0) {
                return 0;
            }
            cur = tree[cur][path];
        }
        return end_cnt[cur];
    }

    // 查询以 pre 为前缀的字符串数量
    int prefixNumber(const string& pre) const {
        int cur = 1;
        for (char c : pre) {
            int path = id(c);
            if (tree[cur][path] == 0) {
                return 0;
            }
            cur = tree[cur][path];
        }
        return pass_cnt[cur];
    }

    // 删除字符串（如果不存在则不执行删除）
    void erase(const string& word) {
        if (search(word) > 0) {
            int cur = 1;
            pass_cnt[cur]--;
            for (char c : word) {
                int path = id(c);
                int next_node = tree[cur][path];
                if (--pass_cnt[next_node] == 0) {
                    tree[cur][path] = 0; // 剪枝，直接断开该分支
                    return;
                }
                cur = next_node;
            }
            end_cnt[cur]--;
        }
    }

    // 多组测试数据时的按需清空（只清空使用过的节点，耗时 O(cnt * A)）
    void clear() {
        for (int i = 1; i <= cnt; i++) {
            memset(tree[i], 0, sizeof(tree[i]));
            end_cnt[i] = 0;
            pass_cnt[i] = 0;
        }
        cnt = 1;
    }
};
```

### 栈溢出风险

**不能直接在函数内部定义为普通局部变量**（如直接在 `main()` 里写 `Trie<150005> trie;`），这样会直接导致**栈溢出（Segmentation Fault）**。

#### 原因分析

- 该模板内部包含固定大小的原生数组：

    - `tree[150005][26]` 占用约 $150005 \times 26 \times 4 \approx 15.6\text{ MB}$

    - `end_cnt` + `pass_cnt` 占用约 $1.2\text{ MB}$

    - 整个结构体大小约为 **16.8 MB**。

- 评测环境（Linux/Windows）的默认栈空间通常只有 **8 MB**（部分 OJ 只有 1~2 MB）。

- 如果在 `main()` 等函数内直接写：

    ```c++
    int main() {
        Trie<150005> trie; // ❌ 错误：分配在栈上，直接栈溢出崩溃
    }
    ```

#### 正确的使用方式

##### 方式 1：声明为全局变量（最推荐，算法竞赛常用）

```c++
#include <iostream>
// ... 引入 Trie 模板 ...

// 声明在全局作用域（静态存储区，空间由系统堆内存上限决定，不会爆栈）
Trie<150005> trie;

int main() {
    // 直接使用 trie
    trie.insert("apple");
    return 0;
}
```

##### 方式 2：在局部加上 `static` 关键字

```c++
int main() {
    // 加上 static，变量存放在静态区而非栈上
    static Trie<150005> trie;

    trie.insert("apple");
    return 0;
}
```

##### 方式 3：使用 `new` / `std::unique_ptr` 在堆上分配

```c++
int main() {
    // 动态在堆上申请内存
    auto trie = std::make_unique<Trie<150005>>();

    trie->insert("apple");
    return 0;
}
```

## 编译报错：`Compiler exceeded OUTPUT limit`

这一系列令人抓狂的 `Compiler exceeded OUTPUT limit` 报错，根源在于 **C++ 语言标准中关于“平凡类型（POD / Trivially Constructible）”的定义，以及它对“全局大对象初始化”生成的底层汇编代码量的致命影响**。

以下是深层技术原理的完整还原与详细剖析。

### 报错问题

```text
编译错误:您提交的代码无法完成编译
Compiler exceeded OUTPUT limit
```

### 一、报错本质：什么是 `Compiler exceeded OUTPUT limit`？

国内各大算法评测系统（牛客、Codeforces 等）评测代码时，是通过限制子进程的资源来保护服务器的。

- 评测机不仅限制了运行时的内存和 CPU 时间，还限制了**编译时编译器向标准输出/标准错误（stdout/stderr）或中间输出流吐出数据的上限（通常设为 10MB～32MB）**。

- 如果编译器在编译你的代码时，生成的警告日志量、调试符号流或**内部临时汇编输出流**超过了这个阈值，系统就会强行掐断编译进程，报出 `Compiler exceeded OUTPUT limit`。

### 二、两次踩坑的核心机制拆解

你的结构体所占内存高达：

$$\text{MAXN} \times 26 \times 4 \text{ 字节} + 3 \times \text{MAXN} \times 4 \text{ 字节} \approx 52\,\text{MB} + 6\,\text{MB} = 58\,\text{MB}$$

在 C++ 中，**这 58MB 内存是如何初始化的，完全由你的结构体是不是“平凡类型”决定**。

#### 1. 第一次报错：手动写了构造函数 `Trie() { build(); }`

```c++
template <int MAXN = 500005, ...>
struct Trie {
    ...
    Trie() { // 手写了用户自定义构造函数
        build();
    }
};
Trie trie; // 全局对象
```

- **正常 POD（零初始化）**：如果类型是纯数据结构（POD），全局变量只需要向可执行文件的 `.bss` 段注册一个占位符：“_请操作系统在程序启动时映射一块 58MB 全 0 的内存_”。编译器**一条汇编初始化代码都不需要生成**。

- **一旦有了手写的构造函数**：

    C++ 标准规定，**只要有自定义构造函数，该对象就具有非平凡的动态初始化（Non-trivial dynamic initialization）**。

    哪怕你的构造函数里只写了一行 `cnt = 1;`，编译器在前端 AST 展开、生成静态初始化器（Static Initializer）时，面对一个带模板的 58MB 巨型聚合体，会强行为这个庞然大物生成极为臃肿的构造符号信息、全局初始化函数（`_GLOBAL__sub_I_...`）以及展开的指令块。这瞬间撑爆了评测机为编译器管道设置的大小上限。

#### 2. 第二次报错：删了构造函数，但写了类内初值 `int cnt = 1;`

```c++
template <int MAXN = 500005, ...>
struct Trie {
    ...
    int cnt = 1; // 类内成员就地初始化（NSDMI）
    ...
};
Trie trie;
```

你虽然删掉了手写的 `Trie()`，但是写了 `int cnt = 1;`。

在 C++11 及后续标准中，**类内就地初始化（Default Member Initializer）等价于显式编写了默认构造函数**：

> 编译器会自动为你隐式生成等价于以下的代码：
>
> ```c++
> Trie() : cnt(1) {} // 隐式生成的非平凡默认构造函数
> ```

这个隐式生成的默认构造函数，把原本已经变成普通聚合体的 `Trie` **再次打回了原形**——它依然不是 `Trivially Default Constructible`。编译器再次被逼着去为这 58MB 的全局对象生成庞大的动态初始化例程，导致第二次依然报 `Compiler exceeded OUTPUT limit`。

### 三、为什么最后这份代码能“秒过”编译？

最后这份代码：

```c++
template <int MAXN = 500005, ...>
struct Trie {
    int tree[MAXN][A];
    int end_cnt[MAXN];
    int pass_cnt[MAXN];
    int cnt; // 纯声明，既无默认值，也无构造函数
    int str_id[MAXN];
};

Trie trie; // 全局变量
```

1. **彻底回归 POD / Trivially Constructible**：

    此时 `Trie` 是一个纯粹的平坦内存块（Plain Old Data）。

2. **纯 `.bss` 段映射**：

    编译器看到它是全局变量且没有构造函数，直接将其判定为**静态零初始化（Static Zero-Initialization）**，打包塞进可执行文件的 `.bss` 段。生成的汇编代码中只有一条简短的段大小声明，没有任何多余的展开指令。

3. **零编译开销**：

    编译输出体积从数十兆骤降到几百字节，编译瞬间完成；而在进入 `main()` 后，通过在 `ap()` 里手动执行 `trie.cnt = 1;`，只用一条汇编指令就完成了根节点的设定，逻辑与性能全部达到最优。

### 竞技编程与工程避坑准则

当你在做字符串、图论或数论题目，需要一次性在全局开辟 **30MB 以上** 的大数组时：

1. **避免类内带逻辑的构造函数**：尽量保持结构体为纯数据容器（纯成员声明）。

2. **避免类内就地赋初值**：不要在巨型全局结构体内部写 `int cnt = 1;` 或 `bool vis = false;`。

3. **统一入口初始化**：提供显式的 `init()` 或 `build()` 成员函数，并在 `main()` 或测试点入口显式调用。
