**以这个为例**

```c++
BIT<int> tr(n);
tr.build(b);
```

在 `tr.build(b)` 中，`.` 是 C++ 中的**成员访问运算符（Member Access Operator / Dot Operator）**。

它的核心作用是：**让一个具体的“对象实例”，去调用定义在它所属“类/结构体”内部的成员函数或访问其成员变量。**


### 1. 语法与语义拆解

```text
  tr    .    build   (b);
└──┬──┘ └┬┘ └───┬───┘
   │     │      └─ 结构体 BIT 内部定义的成员函数名
   │     └──────── 成员访问运算符（点操作符）
   └────────────── 之前创建的具体对象实例（BIT<int> 类型的变量）
```

- **左侧 (`tr`)**：必须是一个**对象实体**（非指针）。

- **右侧 (`build`)**：必须是该对象所属类/结构体中定义的**公开（public）成员**。


### 2. 这里的底层发生了什么？（隐式 `this` 指针）

在 C++ 内部，成员函数并不是为每个对象各复制一份，而是所有对象共享一套函数代码。

当你执行 `tr.build(b);` 时，编译器在底层实际上做的是**将对象 `tr` 的地址作为隐藏参数（即 `this` 指针）传递给 `build` 函数**：

```c++
// 编译器底层的实际调用逻辑等价于：
BIT<int>::build(&tr, b);
```

因此，在 `build` 函数内部访问的 `bit` 和 `n`：

```c++
bit[i] += a[i]; // 实际上操作的是 this->bit[i]，即 tr.bit[i]
```

正是因为这个 `.` 操作，函数才知道修改的是 `tr` 这个具体对象里的 `bit` 数组，而不是其他树状数组对象。


### 3. 拓展对比：`.` 与 `->` 的区别

|**操作符**|**使用场景**|**示例**|
|---|---|---|
|**`.` (点操作符)**|左侧是**对象本身 / 引用**|`BIT<int> tr(n);`<br><br>  <br>  <br><br>`tr.build(b);`|
|**`->` (箭头操作符)**|左侧是**指向对象的指针**|`BIT<int>* ptr = &tr;`<br><br>  <br>  <br><br>`ptr->build(b);` _(等价于 `(*ptr).build(b)`)_|
